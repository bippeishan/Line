功能缺口

按“阻断上线 → 削弱闭环 → 后置验证”排序。P0 是交给种子用户之前必须处理的四件事。

已修复01

图解文件已出库到对象存储

新增 018_pattern_file_storage.sql：pattern_files 只保留 object_key、mime_type、size_bytes，字节写入与封面同一套对象存储（本地目录或 S3）。上传走 POST /api/pattern-files，读取走 GET /api/pattern-files/{id}/file 并做归属校验，前端改用 URL 引用而非 base64。

存量数据：首次读取或 API 启动时惰性迁移，把 file_data 写入对象存储后置空；每账号 200 MB 配额，单文件解码上限 20 MB。
顺带修复：整目录挂载后 init.sql 排在 017 之后，加上 row_number 未加反引号、011/012/013 与基线重复定义，新库首次初始化实际是失败的——基线已重命名为 001_init.sql，001–018 现可一次跑完。

已修复02

CI 已上线，四个任务合入即跑

新增 .github/workflows/ci.yml：后端 gofmt/go vet/go test -race；前端 eslint（补了缺失的 flat config）、tsc -b、vite build；迁移任务用临时 MySQL 8.4 容器和 scripts/verify-migrations.sh 全量执行 001–018 并断言 25 张表与关键字段；端到端任务真实启动 API 与前端后跑 Playwright。

顺带修掉：npm run lint 之前完全跑不起来（没有配置文件），补齐后捕获到一个真实 bug——useSuggestion 这个假 Hook 在回调里被调用，已重命名为 applySuggestion；同时把 React Compiler 风格的 purity/set-state-in-effect 降为非阻断，避免把全库的挂载拉取写法变成红灯。
本地复现：./scripts/verify-migrations.sh 会自建 line_verify 临时库跑完整流程，不动已有数据。

已修复03

提醒已能发邮件，投递状态可见

新增 019_reminder_delivery.sql：project_reminders 增加 remind_at、channel、email_sent_at、attempts、last_error。后台调度器每分钟扫描到期提醒（最多 5 次重试、每次 50 封、只投递已验证邮箱），成功写活动流与审计，失败记录原因；界面新增「发送时间 / 渠道」与投递状态标签，并提供 POST …/reminders/{id}/send 立即发送。

顺带修复：SMTP_FROM 带显示名时被直接当作 SMTP 信封发件人，所有邮件（含验证码、重置密码）都会被服务器以 501 invalid FROM parameter 拒绝——已拆分为信封裸地址 + From 头；020_project_defaults.sql 补上 projects.completion_note 等 NOT NULL 列的默认值，此前干净库上「创建项目」会直接报 1364。

P004

生产准备未完成

日志只有 log.Printf，没有结构化字段、错误追踪与指标；备份恢复演练、隐私政策、账号删除的全链路验证都还没做。

做：slog + 错误追踪接入，做一次真实恢复演练，补齐政策页。

P105

AI 问答对 PDF 不可用

contentAsk 遇到 PDF 只回一句“请提供页码或截图”，因为服务端没有文本层抽取；回答也没有接入针法词典做校验、没有引用位置与免责声明，只有前端一条 Alert。

做：服务端抽取 PDF 文本层 → 命中区间回引；先跑规则校验再交给模型。

P106

图解创作停在草稿

目前只有“文字 → 编号步骤”的预览，缺少排版导出与模板，可视化图表编辑器也不存在——阶段 5 的“最小版本”尚未闭环。

做：先出可导出的 PDF 排版（模板 + 针法词典渲染）。

P107

学习路径是空壳

内容页底部三个入口（基础针法、图解符号、圆形加针）只有标题，没有内容模型；针法词典与学习路径没有连通。

做：给 stitch_terms 增加讲解字段与学习集合，先从词典导流。

P108

成本核算缺位

有时长、有余量、有补货预算，但没有线材成本与实际工时成本的合成视图，月度洞察只有作品数与工时。

做：项目成本 = 用量 × 单价 + 工时 × 估价，并入月度看板。

P109

API 契约与分页未统一

80 个端点没有 OpenAPI 文档，列表接口用硬编码 LIMIT 24，错误码散落在字符串里；前端无法据此生成类型。

做：补 OpenAPI 骨架 + 统一分页与错误码字典。

P210

作者平台与交易

没有作者主页、图解发布/试读/版本更新、支付与版权申诉流程；patterns 表只是内容种子。

留：等试点数据证明内容供给与付费意愿后再开。

P211

社区完全没有开始

挑战、作品打卡、同款求助、评论与内容审核都不存在——按路线图属于阶段 6，符合当前边界。

留：先有稳定内容供给与留存，再做社区。

P212

离线同步只做了一半

IndexedDB 队列与 Service Worker 已有，队列也带 blocked 标记，但界面没有同步状态面板，用户看不到“还没有发出去的修改”。

做：暴露队列状态与重试入口，弱网场景先给预期。

产品边界与优先级

首发用户与核心场景

项目决策
首发人群钩织玩偶新手与进阶爱好者；已有 PDF/图片图解、会在多个作品间切换
核心任务计数不出错、停工后快速恢复、知道所用线材与针号、完成后留下可复用记录
首发终端响应式 Web 优先，重点适配手机竖屏；桌面端用于图解阅读和项目整理
不做的事首发不做公开社区、支付、图解市场、OCR 识别、AI 问答、可视化图解编辑器

优先级原则

闭环优先每项功能必须改善开工、持续钩织或停工恢复之一。
数据优先先让项目、行数、材料与图解形成可关联的数据资产。
规则可信计算器结果展示输入、公式/规则来源和适用条件；异常值需提示。
可扩展但不预建为后续作者、交易与 AI 预留领域模型，避免提前实现复杂工作流。

10

阶段 5–6：创作、商业与生态

  1. 作者发布试点：作者主页、图解上传、试读、版本更新和授权说明；先邀约 5–10 位作者，不开放自由入驻。
  2. 受控 AI 助手：现有接入需要先补齐 PDF 文本抽取、规则校验与引用，再对用户开放。
  3. 图解创作最小版本：先从文字针法/模板填写生成排版良好的 PDF，再评估拖放图表编辑器。
  4. 付费实验：会员或作者数字内容售卖二选一验证，不同时上线两套结算体系。
  5. 社区：主题挑战、作品打卡、同款求助、作者经营工具、课程与材料合作，配套审核与纠纷处理。

商业化护栏

  • 图解交易前完成版权投诉、下架、授权范围、退款与税务责任设计。
  • 水印应可追溯且不影响正常阅读；不将其作为唯一版权保护手段。
  • AI 不声称替代人工校对；针数/尺寸建议要求用户确认密度和样本条件。

功能阶段要解决前置条件
4 · 线材结构化
待排期		阶段 4把品牌 / 线名 / 线重（lace–bulky）/ 色号拆成可枚举字段，才能按图解要求的线重筛选、按色系检索、按米克换算用量。现在全是自由文本。021 之后的迁移编号；线重枚举与 CYC 标准对齐；老数据回填策略

未开始		阶段 5用户自己画/改配色图：选择、涂料、填充、翻转旋转、查找替换、符号键，配键盘快捷键。现在只有只读阅读器 + 坐标标注。图解数据模型从「文件」升级为「格子矩阵」；阶段 4 标注先稳定

未开始		阶段 5–6让色块像真实纱线（花杂、混色、marled）而不是纯色。当前用用户自己的线材照片裁片做纹理，只覆盖用户拍过的线。授权色卡图库或拍摄流程；纹理压缩与移动端性能预算
